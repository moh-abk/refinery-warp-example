# GDC Air-Gapped Operations Center 3.0: Config Host (CONFIG1) Setup (Simple Guide)

* **Estimated time:** ~4 hours
* **Owner:** OIC team
* **Comes after:** 4. OI Hyper-V installation
* **Source:** [Google Cloud Distributed Cloud Hosted Docs](https://docs.cloud.google.com/distributed-cloud/hosted/docs/latest/gdcag/infrastructure/operations-center-setup-30/setup-confighost)

---

## What This Does

`CONFIG1` is the "control" virtual machine (VM) that builds the rest of the Operations Suite Infrastructure (OI) environment. In this guide, you will:

1. Populate the main settings file (`config.ps1`) with your site's details.
2. Secure the `CONFIG1` VM.
3. Install Windows Server 2022 on it.
4. Copy files to the VM and run its setup scripts.
5. Verify VM functionality.
6. Prepare the files required to build downstream VMs.

---

## Before You Start

Have these prerequisites ready. **Do not continue until `config.ps1` is complete and correct.**

1. **Network Plan:** Generated by `occonfigtool`, specifically `ocinfo.common.opscenter.local.txt`. (Network names in this guide, such as `OCCORE-SERVERS`, match the **Name** column in that file.)
2. **DNS & Cell Domain Info:** The domain name and DNS server IP of **every** GDC cell managed by this OI (located in the Customer Intake Questionnaire / CIQ outputs).
3. **Customer-Provided Values:**
   * Subnets and gateways (`OCCORE-SERVERS`, `OCCORE-JUMPHOSTS`, `OC-WORKSTATIONS`)
   * Message of the Day (title and body text)
   * Windows product key (KMS key), if available
4. **Deployment Scope:** If performing a **multi-site** deployment, prepare to edit every section of `config.ps1` tagged `### Multi-Site`.

> [!NOTE]
> Perform all of **Part 1** on the **BM01** host while logged in as **Administrator**.

## Part 1: Create and Fill In `config.ps1` (On BM01)

### Step 1: Copy the Example File

* **Source:** `H:\operations_center\dsc\config.example.ps1`
* **Destination:** `H:\operations_center\config\config.ps1`

---

### Step 2: Configure Values in PowerShell ISE

Open `H:\operations_center\config\config.ps1` in PowerShell ISE and modify the following parameters:

#### A) Basic Settings

1. **`Site1Code`** (at the top of the file):
   * Default: `DC1`.
   * > [!WARNING]
     > Must use **exactly 2 letters + 1 number** (e.g., `DC1`, `AA1`). Exceeding 3 characters causes NetBIOS computer names to exceed the Windows 15-character limit.
2. **`HardwareVersion`**:
   * Default: `3.0`. Update if using legacy hardware.
3. **`NetbiosDomain` and `DnsDomain`**:
   * Modify only if deviating from defaults.
   * If modified, perform a global find-and-replace for `opscenter` and `opscenter.local` across the entire file (they are hard-coded in several locations).

#### B) Splunk

4. **`SplunkPeers`**:
   * Add an entry for each Distributed Cloud zone.
   * If zones are not yet configured, leave as default (refer to guide `SIEM-G0007`).

#### C) DNS

5. **`DnsConditionalForwarder`**:
   * Requires **at least one** entry. Remove unnecessary example blocks.
   * *Multi-site:* Provide one entry per cell.
   * Entry schema:
     * `Domain`: GDC cell DNS domain (`dns.delegatedSubdomain` in `ciq.yaml`).
     * `Master`: List of DNS server IPs (from `cellcfg` for type `DNSReservation`).
   * *To retrieve the DNS IP from the root admin cluster, run:*
     ```bash
     export KUBECONFIG=/root/release/root-admin/root-admin-kubeconfig
     kubectl get -n dns-system service gpc-coredns-external-udp -o jsonpath='{.status.loadBalancer.ingress[0].ip}{"\n"}'
     ```
6. **`DNSServers`**:
   * Supply the 2 IP addresses for primary and secondary Domain Controllers (e.g., `<SITE1>-DC1` and `<SITE1>-DC2`).
   * *Multi-site:* Stagger DNS servers by site according to instructions in the example file.

#### D) Time (NTP)

7. **`NTPServers`**:
   * Retrieve the cluster IPs from the root admin cluster:
     ```bash
     kubectl get timeserver -A -o json | jq '.items[].address'
     ```
   * Populate using the exact array syntax:
     ```powershell
     NtpServers = @(
       '10.251.80.2',
       '10.251.80.3',
       '10.251.80.4',
       '10.251.80.5'
     )
     ```

#### E) Network

8. **`SubnetPrefix`**: Default is `24`. Match customer `OCCORE-SERVERS` subnet prefix.
9. **`DefaultGateway`**: Customer's `OCCORE-SERVERS` gateway IP. Check secondary-site entries if multi-site.
10. **`WorkstationCider`**: *(Spelled exactly as shown)* Customer's `OC-WORKSTATIONS` CIDR range.
11. **Subnet Find-and-Replace**:
    * `172.21.0.` $\rightarrow$ customer's `OCCORE-SERVERS` prefix
    * `172.21.2.` $\rightarrow$ customer's `OCCORE-JUMPHOSTS` prefix
    * `172.21.32.` $\rightarrow$ customer's `OC-WORKSTATIONS` prefix
    * *Multi-site:* Replace values across both site definitions.

#### F) Message of the Day (MOTD)

12. **MOTD Configuration**:
    * `Caption`: Customer MOTD banner title.
    * `Text`: Full customer MOTD banner text.

#### G) Node Definitions

13. Verify each node entry:
    * **`NodeName`**: Validate hostname. (Names like domain controllers recur in multiple blocks).
    * **`IPv4Addr`**: Node IP address.
    * **`HyperVHost`**: Must be the IP address of the Hyper-V host executing this VM. Retrieve mapping from the "Hyper-V Servers" section.
    * > [!IMPORTANT]
      > Do **not** reallocate a VM to a different bare-metal host. Only swap the host name placeholder for its actual IP.
14. For nodes with `Role = "jumphost"`, confirm secondary NIC mappings match `OCCORE-JUMPHOSTS`:
    * `JumphostIPv4Cidr`
    * `JumphostDefaultGateway`

#### H) DHCP

15. Verify DHCP scope parameters align with `ocinfo.common.opscenter.local.txt`:
    * `ScopeId`, `IpStartRange`, `IpEndRange`, `Router`, `SubnetMask`

#### I) Windows Key

16. **`KmsServerKey`**: Populate with customer KMS / Windows Server key if available.

#### J) Finalize

17. *Multi-site:* Audit all sections prefixed with `### Multi-Site`.
18. **Save** `H:\operations_center\config\config.ps1`.

## Part 2: Secure the CONFIG1 VM (On BM01)

`CONFIG1` was instantiated during bare-metal host initialization but requires hardening.

1. Open **Hyper-V Manager** as Administrator.
2. Confirm `CONFIG1` is in an **Off** state.
3. Open **PowerShell** as Administrator.
4. Replace `CONFIG1_VM_NAME` with your VM identifier (e.g., `DC1-CONFIG1`) and run:

```powershell
$vm = Get-VM "CONFIG1_VM_NAME"

try {
    $hg_owner = Get-HgsGuardian 'OCITGuardian' -ErrorAction Stop
}
catch {
    Write-Verbose 'OCIT HGS certs not found. Creating them.'
    New-HgsGuardian -Name 'OCITGuardian' -GenerateCertificates
    $hg_owner = Get-HgsGuardian 'OCITGuardian' -ErrorAction Stop
}
$kp = New-HgsKeyProtector -Owner $hg_owner -AllowUntrustedRoot

$vm | Set-VM -ProcessorCount 4
$vm | Set-VMMemory -DynamicMemoryEnabled $true
$vm | Set-VMKeyProtector -KeyProtector $kp.RawData
$vm | Enable-VMTPM
$vm | Set-VMSecurity -EncryptStateAndVmMigrationTraffic $true
```

## Part 3: Install Windows on CONFIG1

1. In Hyper-V Manager on **BM01**, right-click the `CONFIG1` VM and select **Settings**.
2. Under **Hardware**, expand **SCSI Controller** and select **DVD Drive**.
3. Select **Image File**, browse to `H:\Media`, and choose `microsoft-windows-server-2022.iso`.
4. Under **Hardware**, select **Firmware** and move **DVD Drive** to the top of the boot order. Click **Apply** $\rightarrow$ **OK**.
5. In Hyper-V Manager, right-click `CONFIG1` and select **Connect...**.
6. Click **Start**, then immediately press any key when prompted:
   ```text
   Press any key to boot from CD or DVD...
   ```
   > [!NOTE]
   > You only have a few seconds. If a white "BIOS failed to boot" screen appears, reset the VM and retry immediately.
7. Complete Windows Setup:
   * **Image:** Windows Server 2022 Datacenter (Desktop Experience)
   * **Installation Type:** Custom: Install Windows only (advanced)
   * **Disk Allocation:** Select the 200 GB partition
8. Following the automatic restart, configure the local `Administrator` password and log in.
9. In **Server Manager**, rename the VM to `<SITE>-CONFIG1` (must match the name specified in `config.ps1`).
10. Enable Remote Desktop:
    * In **Server Manager**, click **Disabled** adjacent to Remote Desktop.
    * In System Properties, select **Allow remote connections to this computer** and accept the firewall exception.

## Part 4: Copy Files and Disable Time Sync (On BM01)

### Step 1: Transfer Setup Assets

Run the following in an elevated PowerShell prompt on **BM01** (replace `CONFIG1_VM_NAME` with your VM name):

```powershell
cd H:\operations_center\dsc
.\Copy-ConfigHostFiles.ps1 CONFIG1_VM_NAME
```

### Step 2: Disable Time Synchronization Integration

Run the following in the same PowerShell console:

```powershell
Disable-VMIntegrationService -VMName CONFIG1_VM_NAME -Name 'Time Synchronization'
```

## Part 5: Run Setup Scripts (On CONFIG1 Only)

1. Connect to the `CONFIG1` console via Hyper-V Manager and log in as `Administrator`.
2. Open PowerShell as Administrator and import modules:
   ```powershell
   C:\release\operations_center\dsc\Install-PowerShellModules.ps1 -Path C:\release\operations_center\dsc\modules
   ```
3. Stage deployment files:
   ```powershell
   C:\release\operations_center\dsc\Initialize-ConfigHostFiles.ps1
   ```
4. Initialize the host (replace `<config1_cidr>` with the CONFIG1 IP and CIDR prefix from `config.ps1`, e.g., `172.21.0.99/24`):
   ```powershell
   cd C:\dsc
   .\Initialize-ConfigHost.ps1 -IPv4Cidr <config1_cidr>
   ```
5. When prompted, enter a password for the **Marvin** user.

   > [!CAUTION]
   > The password **must** satisfy all of the following requirements:
   > * $\ge 14$ characters
   > * At least 1 uppercase letter
   > * At least 1 lowercase letter
   > * At least 1 digit
   > * At least 1 special character
   > * Must **not** include the username or substrings of it
   >
   > Non-compliant passwords trigger forced resets upon domain join, stalling deployment. **Record this password securely.**

6. The script will reboot `CONFIG1` automatically upon completion.

## Part 6: Validate CONFIG1

1. From **BM01**, open an RDP session to `CONFIG1` and log in as `Marvin`:
   ```cmd
   mstsc /v <CONFIG1_IP>
   ```
2. Open an elevated PowerShell session (`Run as Administrator`).
3. Build the MECM component assets:
   ```powershell
   cd C:\dsc
   .\Build-MecmFiles.ps1
   ```
   * **Verification:** Check that `C:\dsc\data\OicManagedApps.yaml` is generated.
4. Compile MOF artifacts across all target OI nodes:
   ```powershell
   cd C:\dsc
   .\Build-Mof.ps1
   ```
   > [!NOTE]
   > Missing certificate warnings and credential generation logs are normal at this stage, as downstream infrastructure has not yet been provisioned.

## Part 7: Prepare Bare-Metal Host Deployment Files

`CONFIG1` distributes payload files required by Hyper-V hosts to provision remaining virtual machines.

1. In the active RDP session on `CONFIG1` (as `Marvin`), run in an elevated PowerShell session:
   ```powershell
   cd C:\dsc
   .\Copy-BareMetalFiles.ps1
   ```
   * When prompted, enter the local `Administrator` credentials configured during bare-metal host setup.
   * Safe to ignore: `WARNING: Unable to find certificate or thumbprint for <HOSTNAME>; Using defaults.`

2. Extract the initial base64-encoded VM local `Administrator` credential:
   ```powershell
   [xml]$x = Get-Content -Path C:\config\hyper_v\server2022.template.xml
   $encoded_pass = $x.unattend.settings[1].component[0].UserAccounts.AdministratorPassword.Value
   $pass = [System.Text.Encoding]::Unicode.GetString([System.Convert]::FromBase64String($encoded_pass)).Replace('AdministratorPassword', '')
   Write-Host "The initial administrator password is: $pass"
   ```

> [!WARNING]
> Save this initial administrator password for provisioning activities. It must be rotated across all systems post-deployment.

## Common Pitfalls

| # | Issue | Remediation |
|---|---|---|
| 1 | **Site code $> 3$ characters** | NetBIOS hostnames will exceed 15 characters. Constrain to 2 letters + 1 number. |
| 2 | **Incomplete domain name search-and-replace** | Run a global search for `opscenter` and `opscenter.local` across all of `config.ps1`. |
| 3 | **Altering Hyper-V host placement** | Only replace host placeholder names with host IP addresses; do not move VM roles to different physical hosts. |
| 4 | **Overlooking multi-site blocks** | Audit every `### Multi-Site` tag, secondary gateways, and both sets of subnets. |
| 5 | **Securing an active VM** | Power off `CONFIG1` before running the security/HGS commands in Part 2. |
| 6 | **Missing the ISO boot interrupt** | Re-arm and reboot the VM; send keystrokes immediately upon power-on. |
| 7 | **Non-compliant Marvin password** | Enforce $\ge 14$ characters with all 4 complexity sets to avoid password expiry locks. |
| 8 | **Script execution on wrong target** | `Initialize-ConfigHost.ps1` must execute **inside the CONFIG1 VM**, never on BM01. |
| 9 | **Treating MOF warnings as errors** | Missing certificate warnings in `Build-Mof.ps1` are standard during bootstrap. |
